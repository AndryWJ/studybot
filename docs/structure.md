# Що де лежить у проєкті

Код бота лежить у `src/`, схема бази в `migrations/`, налаштування для Cloudflare у `wrangler.jsonc`. Усе інше або допомагає перевіряти бота (тести, скрипт наскрізної перевірки), або з'являється само після команд і в git не потрапляє.

## Дерево

```
studybot/
├── README.md                 вітрина проєкту
├── docs/                     документація
├── src/                      код бота
│   ├── index.ts              вхід: вебхук, /setup, /charts, щохвилинний запуск
│   ├── bot/                  розмова з користувачем
│   │   ├── router.ts         куди віддати повідомлення чи натискання кнопки
│   │   ├── context.ts        спільне для обробників: час, крок діалогу, виклик ШІ з лімітом
│   │   ├── ui.ts             головне меню, довідка, список команд
│   │   └── features/         розділи бота, по файлу на розділ
│   ├── ai/                   звернення до ШІ і тексти запитів
│   ├── web/                  сторінка графіків і підпис посилань на неї
│   ├── planner.ts            розрахунок годин, розклад по днях, пріоритети
│   ├── grades.ts             середній бал і потрібні оцінки
│   ├── parse.ts              розбір дат, занять і тривалості з тексту
│   ├── reminders.ts          коли нагадувати, текст зведення
│   ├── time.ts               часові пояси, українські дати
│   ├── db.ts                 усі запити до бази
│   ├── telegram.ts           клієнт Telegram Bot API
│   ├── format.ts             Markdown і формули в HTML для Telegram
│   ├── cron.ts               щохвилинна робота
│   └── env.ts                опис налаштувань і секретів
├── migrations/               схема бази (SQL)
├── test/                     автоматичні тести
├── scripts/e2e.mjs           наскрізна перевірка на локальному сервері
├── wrangler.jsonc            налаштування Worker-а для Cloudflare
├── package.json              залежності й команди npm run ...
├── package-lock.json         точні версії залежностей
├── tsconfig.json             налаштування перевірки типів
├── vitest.config.ts          налаштування тестів
├── .dev.vars.example         зразок локальних секретів
├── .gitignore                що не потрапляє в git
│
├── photo_*.jpg               скріншоти з вихідними вимогами (лише локально)
├── node_modules/             з'являється після npm install
├── .wrangler/                з'являється після wrangler dev, тестів, npm run e2e
├── worker-configuration.d.ts з'являється після npm run types
└── .dev.vars                 створюєте ви для локального запуску
```

## Що лежить у git, а що з'являється саме

| Шлях | У git | Звідки береться | Як з ним працювати |
|---|---|---|---|
| `src/`, `migrations/`, `test/`, `scripts/`, `docs/` | так | пишуться руками | редагувати, потім `npm test` |
| `wrangler.jsonc` | так | пишеться руками | змінювати налаштування, потім `npm run deploy`; секретів тут немає |
| `package.json`, `package-lock.json` | так | `npm install <пакет>` змінює обидва | руками не правити lock-файл |
| `tsconfig.json`, `test/tsconfig.json`, `test/env.d.ts`, `vitest.config.ts` | так | пишуться руками | рідко потрібні зміни |
| `.dev.vars.example` | так | зразок | скопіювати в `.dev.vars` і заповнити |
| `node_modules/` | ні | `npm install` | не редагувати; при проблемах видалити й виконати `npm install` знову |
| `.wrangler/` | ні | `wrangler dev`, тести, `npm run e2e` | локальна база й тимчасові файли; можна видалити, з'явиться знову |
| `worker-configuration.d.ts` | ні | `npm run types` (також у `npm run typecheck`) | не редагувати; перегенерувати після зміни `wrangler.jsonc` |
| `.dev.vars` | ні | створюєте ви | локальні секрети для `npm run dev`; нікому не надсилати |
| `photo_*.jpg` | ні | скріншоти вимог, покладені вручну | у них приватне листування, тому вони в `.gitignore` і лишаються лише на вашому комп'ютері |

## Файли по одному

### Код бота (`src/`)

| Файл | Що це і навіщо |
|---|---|
| `index.ts` | Точка входу. Приймає оновлення від Telegram на `/webhook` (перевіряє секретний заголовок і обробляє у фоні), показує сторінку налаштування `/setup`, віддає графіки `/charts`, запускає щохвилинну роботу. |
| `env.ts` | Опис усіх налаштувань із `wrangler.jsonc` і секретів, щоб редактор підказував назви. |
| `bot/router.ts` | Розбирає, що прийшло: команда, кнопка меню, натискання inline-кнопки, відповідь на кроці діалогу, відповідь у тесті чи просто питання, і викликає потрібний розділ. |
| `bot/context.ts` | Спільне для всіх розділів: поточний час користувача, збереження кроку діалогу, виклик ШІ з денним лімітом і індикатором "друкує...". |
| `bot/ui.ts` | Кнопки головного меню, текст довідки, список команд для меню Telegram. |
| `bot/features/schedule.ts` | Розклад: перегляд, додавання текстом, складання з ШІ, видалення, "сьогодні". |
| `bot/features/deadlines.ts` | Дедлайни: додавання з вільного тексту, важливість і складність, список за пріоритетом. |
| `bot/features/tasks.ts` | Розбивка завдання на кроки з датами і картка плану підготовки. |
| `bot/features/plan.ts` | Майстер плану підготовки до НМТ чи іспитів і поради ШІ, що вчити. |
| `bot/features/study.ts` | Конспект, тест-вікторина з балами, репетитор для вільних питань. |
| `bot/features/progress.ts` | Таймер, ручний запис часу, відсоток виконаного, текстові графіки. |
| `bot/features/grades.ts` | Оцінки й розрахунок потрібних оцінок. |
| `bot/features/settings.ts` | Часовий пояс, ранкове зведення, нагадування про заняття, вільний час, шкала оцінок, видалення даних. |
| `ai/client.ts` | Звернення до Groq, Gemini, іншого OpenAI-сумісного сервісу чи Workers AI з переходом до наступного при збої. |
| `ai/prompts.ts` | Тексти запитів до ШІ, перевірка JSON-відповідей, факти про НМТ. |
| `web/charts.ts` | HTML-сторінка з графіками часу, виконаних завдань і оцінок. |
| `web/sign.ts` | Підписані посилання на графіки, щоб ніхто не відкрив чужі. |
| `planner.ts` | Алгоритми без ШІ: години на предмети, розклад по днях, розподіл кроків, пріоритет дедлайну. |
| `grades.ts` | Середній бал, розбір введених оцінок, скільки треба для бажаної підсумкової. |
| `parse.ts` | Розуміння дат і часу українською ("в п'ятницю о 10", "до 15 грудня"), занять і тривалості. |
| `reminders.ts` | Коли нагадувати про дедлайн, тексти нагадувань і ранкового зведення. |
| `time.ts` | Перетворення між UTC і місцевим часом, переходи на літній час, назви днів і місяців. |
| `db.ts` | Усі SQL-запити. Кожен запит до даних користувача фільтрує за його id. |
| `telegram.ts` | Тонкий клієнт Bot API: надсилання, редагування, тести-вікторини, завантаження файлів. |
| `format.ts` | Перетворення Markdown і LaTeX із відповідей ШІ в HTML, який приймає Telegram, нарізка довгих текстів. |
| `cron.ts` | Те, що Cloudflare запускає щохвилини: нагадування, зведення, нагадування про заняття, прибирання. |

## Часті непорозуміння

| Симптом | Причина | Що зробити |
|---|---|---|
| Змінив `wrangler.jsonc` чи код, а бот поводиться по-старому | Зміни ще не опубліковані | `npm run deploy` |
| Помилка `no such table` | Міграції не застосовані до цієї бази (локальна і віддалена бази різні) | `npm run db:migrate` для робочої, `npm run db:migrate:local` для локальної |
| Змінив `migrations/0001_init.sql`, а в базі нічого не змінилося | Уже застосовану міграцію wrangler повторно не виконує | Створіть нову: `npx wrangler d1 migrations create studybot опис_зміни`, напишіть у ній SQL і виконайте `npm run db:migrate` |
| Хочу записати токен у `wrangler.jsonc` | Файл лежить у git, його бачать усі | Тільки `npx wrangler secret put НАЗВА`; локально в `.dev.vars` |
| `git status` показує `node_modules/` чи `worker-configuration.d.ts` | Згенеровані файли випадково додано | Вони вже в `.gitignore`; приберіть із git: `git rm -r --cached node_modules worker-configuration.d.ts` |
| Локально запущений бот не відповідає в Telegram | Telegram надсилає повідомлення лише на публічну HTTPS-адресу, а локальний сервер її не має | Для перевірки без Telegram `npm run e2e`; для справжньої перевірки `npm run deploy` |
| Редактор підкреслює `D1Database` чи `Ai` як невідомі | Немає згенерованих типів | `npm run types` |
| Після правки `docs/usage.md` падає `npm test` | Тест `usage-guide.test.ts` бере приклади фраз з інструкції дослівно | Онови ту саму фразу в тесті або поверни її в інструкцію |
